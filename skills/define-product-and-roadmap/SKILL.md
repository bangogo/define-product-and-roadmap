# 定义产品与路线图

交付让产品、业务、体验和研发读者能找到用户问题、可见结果、运转逻辑、规则、生效条件、异常恢复、验收与待决事项的文档。所有 PRD 场景默认交付**单份 HTML 审阅稿**；用户明确指定其他格式时遵从要求。仅在用户需要版本编排时另行交付 Roadmap。

## 按需读取

- 涉及用户、证据、产品形态与场景判断：读 [意图与场景契约](references/intent-and-scenario-contract.md)。产品阶段 A/B 与文档操作是不同维度。
- 新建、修订、重写或审计 PRD：读 [PRD 产品契约](references/prd-contract.md)。制作 HTML 时再读 [HTML 工作流与确认契约](references/html-prd-workflow.md)，从 [HTML 模板](assets/prd-template.html)按需改写；模板不是固定目录。
- 涉及版本编排：读 [Roadmap 契约](references/roadmap-contract.md)。仅需旧格式兼容时读 [Markdown PRD 模板](assets/prd-template.md)与 [Roadmap 模板](assets/roadmap-template.md)。
- 重写、反馈采纳、最终审查：按需读 [修订经验](references/revision-lessons.md)与 [质量评审](references/quality-rubric.md)。

## 工作流

1. **定入口和证据。** 确认任务是新建、增量修订、重大重写或仅审计；指出唯一当前审阅文件、读者、交付目的、下一闸门。仅审计不修改文件。按已确认决定、观察证据、文档记载、历史材料、候选和待调研分层，记录来源与日期。存量产品先只读摸排真实现状；产品阶段不能代替文档操作判断。
2. **盘点继承。** 修订和重写都在 HTML 内提供逐项迁移表；重大重排先给新旧目录和各章用途，确认结构后再写正文。有效内容的意义或去留未确认时保留待决。
3. **逐项落位。** 将新反馈拆成事实、决定、规则、例外与示例，指定唯一权威位置和受影响验收。旧规则变化改原定义；同粒度新维度加列，新对象加行；主链或责任变化同步改图、文字和引用。跨章语义合并，不能只换标题或复制段落。已有配套规范的字段、状态、交接和逐步失败处理留在规范；PRD 写产品目标、行为、可见结果、产品级失败选择、边界与验收。
4. **处理高影响未知项。** 答案会改变用户、价值、范围、交付物、授权、主流程分支、验收或有效内容去留时，用决定卡列证据、可信方向、建议、影响和拟落位处，等待用户明确选择。两个以上可信方向时比较 2—3 个，不编造选项。未决项留在审阅稿；低风险措辞、排版、引用修复继续。
5. **写产品要求。** 先说明谁遇到什么问题、得到什么，再写角色、触发或输入、产品动作、可见状态、何时生效、异常后怎样继续、可观察验收。流程环节按问题、输入、责任、功能、结果、完成标准和失败处理审视。把候选、目标、已观察效果分开。涉及交付或外部发布时区分可见、可交接、当前修订已确认、可供发布、已发布。
6. **选表达。** 复杂流程和责任关系优先 SVG，同轴比较优先表格，简单规则用短文。核对图的节点、连线、分支与正文；SVG 提供文字路径。实际检查桌面、390px 和打印的容纳与阅读顺序。案例布局偏好只在其案例内适用。
7. **验证和交付。** 对确切文件做静态检查，再分别进行语义审查和实际渲染检查。决定记录须与当前审阅稿的方向、处理方式、内容和内容指纹匹配。每次只交付一个当前审阅入口，列明状态、未决项、验证层级和下一闸门。只有用户明确认可确切版本的内容与视觉效果，且阻塞待决项处理完毕，才能标最终版。文档批准仅授权被指明的下一闸门。

## 校验入口

```bash
python3 <技能目录>/scripts/stamp_html_prd.py <PRD.html>
python3 <技能目录>/scripts/validate_product_docs.py --prd-html <PRD.html> [--decisions <决定记录.json>] [--format json]
```

每次修改 HTML 后重算指纹，再出新审阅稿和决定记录；旧记录必须失效。没有 Roadmap 也可校验 HTML PRD。若用户选择 Markdown 等非 HTML 格式，交付所选格式并做相应语义、证据和验收检查；实质待决项在对话中逐项确认并保留来源记录，不省略确认。旧 Markdown PRD 与 Roadmap 对仍用 `--prd <PRD.md> --roadmap <Roadmap.md>` 校验；该旧入口的配对要求不应用于 HTML 或其他单份 PRD。验证器只证明机械契约，不能证明页面视觉、宿主执行、外部平台行为或用户效果。

## 边界

- 未获证实的自动化、数字、Deep Research、工具接入或开源复用只按其证据状态表述；实际运行声明须有宿主调用轨迹。
- 用户未请求文件清理时保留历史文件；请求清理时比较覆盖、独有内容和历史价值，迁移后执行已授权的清理并核对链接。
- 未获授权时不执行真实账户、外部提交、交易或发布。对话明确决定可录入同一决定台账并标明来源，不能伪称网页导出。
